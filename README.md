# PDF Merger — отдельные лабораторные анализы и обследования с опциональным AI-переименованием

Windows-утилита с интерактивным **PowerShell-интерфейсом, организованным по образцу Genome**: `start.cmd` открывает PowerShell, проверяет папки, сообщает число найденных PDF и запрашивает подтверждение перед обработкой. По умолчанию сортировка полностью локальная: лабораторные анализы за один день объединяются, а каждое обследование остаётся отдельным PDF. Если тип документа не подтверждён, он отправляется в отдельную папку для проверки и **не смешивается с анализами**. **AI-режим** используется только по явному согласию для установления даты при неподходящем имени, с передачей имени и ограниченного фрагмента текста внешнему API (сам PDF не загружается).

## Surya OCR 2.5 на CPU — экспериментальный изолированный тест

Новый `test-surya-cpu.cmd` запускается двойным щелчком на Windows **без GPU**. Он не меняет рабочую модель, `.env`, `.venv`, `input` и `output`.

При явном запуске устанавливает официальный `llama-server` из зафиксированного Windows CPU x64 архива (SHA-256 проверяется до запуска), создаёт `.venv-surya-cpu` и ставит `surya-ocr==0.24.0`. Используются `Surya 2.5 GGUF Q8_0` и обязательный `vision projector` с Hugging Face, бэкенд `llama.cpp` исключительно на CPU. Скрипт генерирует и распознаёт только вымышленную страницу ЭКГ, сохраняет локальные результаты в `logs/surya-cpu-pilot/`.

До первого запуска нужны 64-битная Windows, Python 3.10+, доступ в интернет и место на диске. Менее 8 ГБ RAM — стоп; 8–16 ГБ — предупреждение; для эксперимента разумнее 16+ ГБ RAM. Размер файлов весов (~0,84 ГБ вместе с проектором) не равен объёму RAM, требуемому для инференса. Скорость на конкретном CPU нужно измерить.

После обновления проекта можно запустить двойным щелчком `C:\Python\PDF_merger\test-surya-cpu.cmd`, либо одной строкой PowerShell:

```powershell
& "C:\Python\PDF_merger\test-surya-cpu.cmd"
```

**Назначение:** проверить локальное OCR русского медицинского текста и таблиц. Surya не удаляет персональные сведения сама по себе и не заменяет семантическую классификацию PDF. На реальные документы и автоматическую анонимизацию пилот не переключается. Перед облачной обработкой потребуется локальное физическое удаление ПДн из документа и независимая проверка результата. Для коммерческого использования весов Surya следует проверить условия лицензии Datalab.
## Запуск с автоматическим обновлением

**`update-and-start.cmd`** — новый запуск в один клик: сначала безопасно обновляет Git-ветку `main` через `git pull --ff-only origin main`, затем вызывает привычный `start.cmd`. Работает даже если терминал открыт в `logs` или запуск сделан через ярлык рабочего стола — путь определяется относительно самого CMD-файла.

- Нужен установленный **Git for Windows** и существующий Git-клон PDF Merger. Если Git отсутствует, обновление остановится с сообщением, приложение не запустится.
- Если есть локальные изменения в отслеживаемых файлах или посторонние неотслеживаемые файлы, обновление **безопасно останавливается**. Ничего не откатывается, ветка не перезаписывается, проблемные файлы перечисляются в консоли для ручной проверки.
- Безопасно переключается на `main`, если проект чист; обновляет **только fast-forward**, без `force`, `reset --hard`, удаления веток или автослияний.
- Пользовательский `.env` с OpenAI-ключом, `input/`, `output/`, `logs/` и `.venv/` исключены из Git и сохраняются.
- Если обновление прошло, появится обычный интерактивный экран PDF Merger с подтверждением обработки. Запуск не разрешает AI сам по себе — выбор и согласие остаются в `start.cmd`.

**Один раз после появления нового файла в GitHub** нужно скачать сам обновлятор на существующий компьютер. В PowerShell выполните эту **одну строку** (из любой папки):

```powershell
git -C C:\Python\PDF_merger pull --ff-only origin main
```

После этого запускайте `C:\Python\PDF_merger\update-and-start.cmd` двойным щелчком — **последующие обновления и запуск будут происходить одной кнопкой**. Если ничего обновлять не нужно, скрипт сообщит `Already up to date` и сразу перейдёт к `start.cmd`.

Обычный `start.cmd` остаётся доступен для работы без Git и без обновления (например, при отсутствии интернета).

## Как пользоваться (Windows 10/11)

1. Скачайте/клонируйте репозиторий и **дважды щёлкните `start.cmd`** (или прежний `merge_windows.bat`).
2. **Первый запуск:** программа создаст отсутствующие папки `input` и `output`, проверит Python 3.10+ и установленные библиотеки. Если требуется первоначальная установка, появится сообщение **«Необходимо установить дополнительные библиотеки на этом компьютере. Это потребуется только один раз. Нажмите Enter для установки»** (либо `0` для отмены). После установки программа завершит первый запуск без обработки PDF; окно останется открытым. Папки и документы не удаляются.
3. Поместите в `input/` PDF. Правильные имена имеют вид `YYYY-MM-DD-Название.pdf`, например `2026-05-19-Биохимия.pdf`. Файлы с другими именами можно обработать через AI, если они содержат достоверную дату.
4. **Следующий запуск:** программа выведет `Обнаружено PDF-файлов: 2`, затем:

   ```text
   Запустить проверку и объединение?
     [1] Да, запустить проверку
     [0] Нет, выйти
   Выберите действие [1/0]:
   ```

5. Нажмите `1` и `Enter` (или введите `Да`). Сначала выполняется локальная проверка имён. Если найдены неверные имена, появится дополнительное меню: `[1]` AI-переименование с передачей фрагментов во внешний API, `[2]` продолжить офлайн с пропуском таких PDF, `[0]` отмена. Для корректно названных файлов дополнительное меню не появляется. Затем начнётся локальная классификация и раздельная обработка. Готовые файлы появятся в `output/Анализы`, `output/Обследования` или `output/На_проверку`; будет показан итог по созданным, пропущенным и ошибкам. **Окно всегда удерживается до `Press any key`**, в том числе при ошибках и отмене.

Если `input/` пуста, после проверки/подготовки окружения программа сообщит об этом и завершится. Когда библиотеки уже установлены и соответствуют `requirements.txt`, повторная установка и запрос Enter не выполняются. При отмене установки ничего не устанавливается. Отмена объединения в главном меню не изменяет PDF, но не отменяет уже подтверждённую первоначальную подготовку окружения.

### Установка Python

Нужен **Python 3.10+** (из `python.org`, команда `py` или `python`): если самого Python нет, программа сообщит об этом и попросит установить его вручную. При первом запуске `start.cmd` автоматически проверяет `.venv` и **все зависимости из `requirements.txt`, включая допустимые версии**. Если окружение не создано или какая-либо библиотека отсутствует/не соответствует требованиям, приложение показывает предупреждение и ждёт Enter. После подтверждения создаёт `.venv`, устанавливает/обновляет зависимости через `pip`, повторно проверяет их и продолжает запуск. Если требования уже выполнены, установка не запускается и интернет не нужен. Повторное подтверждение понадобится только при изменении требований или поломке окружения.

Сейчас единственная внешняя библиотека — `pypdf>=5.9,<8`; **отдельная библиотека `openai` не нужна**, потому что AI API вызывается через стандартную библиотеку `urllib`. Для первого скачивания библиотек нужен интернет (**в `pip` передаётся только список зависимостей, не PDF**). Также можно подготовить окружение заранее через `setup_windows.bat`. Проверка поддерживает обычные спецификации пакетов (PEP 508), но не `-r` и прямые URL в `requirements.txt`; при появлении таких инструкций проверка остановится, а не установит их молча.

## Правила сортировки

**Категория определяется преимущественно по реальному тексту PDF, а не по имени.** Дата `YYYY-MM-DD` берётся из имени; для документов без правильной даты возможен отдельный AI-проход только после согласия пользователя. Сначала локальный классификатор ищет строку **фактически выполненной процедуры** (медицинский код, название, «Врач:»): `7002892 — Рентгенография грудной клетки`, `7014145 — Электрокардиография` и т. д. Даже если в шапке рентгена/ЭКГ присутствует общий пункт «Дата назначения лабораторного исследования», он **не определяет лабораторную категорию**. Аналогично фраза «рекомендовано УЗИ» в заключении рентгенографии не означает, что УЗИ было выполнено. При отсутствии структурированной строки используется консервативное определение по тексту; неоднозначность остаётся в `На_проверку`. Лабораторные результаты определяются по конкретным типам и кодам выполненных анализов, а не по одной шапке.

Результат для одного дня, когда есть биохимия, общий анализ крови и рентгенография грудной клетки:

```text
PDF_Merger/
  input/
    2026-05-19-Биохимия.pdf
    2026-05-19-ОАК.pdf
    2026-05-19-Тесты.pdf           # На самом деле рентгенография
  output/
    Анализы/
      2026-05-19-Анализы.pdf       # Только биохимия и ОАК (вместе)
    Обследования/
      2026-05-19-Рентгенография грудной клетки.pdf  # Один исходный PDF
    На_проверку/
      2026-05-20-Требует-проверки.pdf  # Только неоднозначные документы
```

Файлы обследований **никогда не объединяются** — даже если несколько сделаны в один день. Одинаковые названия исследований одного дня получают числовые суффиксы `-02`, `-03`; исходные PDF не удаляются и не перезаписываются.

Если удалось подтвердить лабораторный тип по тексту PDF, анализы одной даты объединяются в `Анализы/YYYY-MM-DD-Анализы.pdf`. Если точная категория неясна, отсутствует текстовый слой (например, скан без OCR) или одновременно встречаются признаки разных процедур, документ остаётся отдельным в `На_проверку/` для ручного разбора. **Из имени «Lab tests» или «Биохимия» без текстовых доказательств лабораторный тип не выводится**, поскольку предыдущее AI-переименование могло ошибиться.

**Обновление после ошибочной классификации:** исправленная версия по локальному тексту восстановит для уже датированных файлов новые названия результатов в `output/Обследования`, например `2026-11-17-ЭКГ.pdf` и `2026-11-17-Рентгенография грудной клетки.pdf`, с суффиксом `-02` для второго одноимённого исследования. Исходные `input/YYYY-MM-DD-Требует-проверки.pdf` и старые `output/На_проверку` **не переименовываются и не удаляются автоматически**. Сначала проверьте план `--dry-run`. Если дата в имени не совпадает с датой выполнения процедуры, классификатор её **самовольно не исправляет**: изменение даты — отдельная проверяемая задача.

**Уже обработанные 17 PDF:** повторно обращаться к AI для уже правильно датированных исходников не нужно. После обновления обычный запуск будет сортировать их по новой схеме на основании содержимого. Старые смешанные файлы `output/YYYY-MM-DD.pdf` программа не удаляет, не перезаписывает и не считает новыми результатами — после проверки новой структуры старые итоги можно удалить вручную. Файлы `input/` при локальной сортировке не переименовываются.

Если имя не соответствует `YYYY-MM-DD-Название.pdf` или дата некорректна (например, 2025-02-29), документ без включённого AI будет пропущен и помечен в консоли. При AI-переименовании дата обязательно подтверждается текстом исходника; название исследования выбирается по явным локальным признакам. Если их не хватает, используется честное `Требует-проверки`, а не выдуманное «Тесты» или «Лабораторные исследования».

**Проверка полноты и состава:** каждый обычный (не `--dry-run`) запуск создаёт или обновляет локальный `output/Состав_результатов.csv` (UTF-8 для Excel). В нём перечислены **исходные PDF, целевой результат, категория, статус и подтверждение включения**. `СОЗДАНО / ДА` означает, что документ действительно был включён в **только что созданный/пересобранный** результат. `ПРОПУЩЕНО_УЖЕ_СУЩЕСТВУЕТ / НЕ ПОДТВЕРЖДЕНО` означает, что старый результат не перепроверялся: список PDF в консоли — план, а не доказательство наличия страниц в существующем сборнике. Ошибка сохранения необязательного CSV не отменяет успешно созданные PDF. Отчёт остаётся только на локальном компьютере, так как `output/` исключена из Git.

**Исправление числовых диапазонов:** лабораторные PDF могут содержать референсы вроде `110.0 - 160.0`, которые раньше ошибочно разбирались как «дополнительные процедуры» и переводили файлы в `На_проверку`. Теперь числовой код обследования принимается только при достаточной длине, а коды анализов вида `B03.016.002`, `A09.05.042` продолжают распознаваться. Для уже созданных неполных результатов **недостаточно просто запустить сортировку**: существующие сборники без разрешения не перезаписываются. При запуске через `start.cmd` или `update-and-start.cmd` приложение теперь предложит **[1] пересобрать и заменить существующие результаты** либо **[2] оставить старые**. Замена производится только после подтверждения, атомарно. Старые PDF в `output/На_проверку`, созданные предыдущими версиями, автоматически не удаляются; они могут оказаться устаревшими и должны быть проверены после пересборки. Для консоли эквивалент — `pdf_merger.py --overwrite`.

**Повторная обработка:** уже существующие итоговые PDF **не перезаписываются**. Для принудительной замены нового результата запускайте Python напрямую с `--overwrite` (см. ниже). Старые смешанные PDF в корне `output/` не затрагиваются. Без AI исходные PDF не изменяются. При AI-переименовании изменяются только их имена внутри `input/`; содержимое PDF остаётся прежним.

## Командная строка (без интерфейса)

После создания `.venv` можно вызвать Python напрямую:

```powershell
.\.venv\Scripts\python.exe pdf_merger.py --dry-run
.\.venv\Scripts\python.exe pdf_merger.py --check-names
.\.venv\Scripts\python.exe pdf_merger.py --rename-with-ai --dry-run
.\.venv\Scripts\python.exe pdf_merger.py --rename-with-ai
.\.venv\Scripts\python.exe pdf_merger.py
.\.venv\Scripts\python.exe pdf_merger.py --overwrite
.\.venv\Scripts\python.exe pdf_merger.py --recursive
.\.venv\Scripts\python.exe pdf_merger.py --input-dir "D:\Health\input" --output-dir "D:\Health\output"
```

Без `--recursive` обрабатываются PDF только непосредственно внутри `input/`. Результаты записываются атомарно: сначала во временный файл, затем публикуются после сверки числа страниц. Повреждённый или защищённый паролем PDF не создаёт частично объединённого результата; ошибки одной даты не прерывают остальные даты.

### Семантическая классификация Luna (по явному выбору)

По умолчанию программа продолжает **полностью локальную** сортировку, не отправляя медицинские данные наружу. Если нужен смысловой анализ, при запуске `start.cmd` или `update-and-start.cmd` доступны три режима:

- **[1] Локальная классификация** — прежний бесплатный алгоритм, без API.
- **[2] Luna только для спорных PDF** — локальный алгоритм отбирает файлы с категорией `На_проверку`, затем модель определяет, какие процедуры фактически выполнены. Это экономит запросы, но не перепроверяет уверенные локальные решения.
- **[3] Luna для всех PDF** — нейросеть независимо анализирует каждый документ, включая уже отнесённые локально к `Анализы` или `Обследования`. При конфликте модели с однозначными локальными признаками файл остаётся в `На_проверку`; **модель не получает право автоматически смешивать сомнительные документы в один сборник**.

Для каждого положительного решения модель возвращает категорию, краткий тип обследования и **точную цитату названия выполненной процедуры**, которая должна буквально находиться в переданном фрагменте. Одни лишь референсные значения (например, `110.0 - 160.0`), шапка «Дата назначения лабораторного исследования» или упоминание рекомендованного УЗИ не являются доказательством выполненной процедуры. Неподтверждённые ответы изолируются в `На_проверку`, не добавляются в анализы.

**Конфиденциальность и стоимость:** варианты [2] и [3] являются явным согласием на передачу текста медицинского PDF (не файла целиком) в указанный в `.env` внешний AI API, с возможными затратами. Передаётся до 8500 символов из первых двух страниц; для типовых лабораторных выгрузок административная шапка с данными пациента отсекается, но для произвольного PDF **не гарантируется обезличивание**. Без выбора AI-режима сеть для классификации не используется. Ключ остаётся в локальном `.env`.

Ответы сохраняются в **локальном** `logs/ai-classification-cache.json` и повторно используются для **неизменённых PDF, той же модели и версии правил**, без дополнительных AI-запросов. Кэш не содержит имён файлов, исходного текста, цитат, API-ключей или самих PDF. Если запрос завершился сетевой или API-ошибкой, новая итоговая PDF-выгрузка не публикуется; ранее классифицированные документы остаются в кэше, что сокращает повторные расходы.

Команды без интерактивного меню:

```powershell
.\.venv\Scripts\python.exe pdf_merger.py --classify-with-ai review
.\.venv\Scripts\python.exe pdf_merger.py --classify-with-ai all
.\.venv\Scripts\python.exe pdf_merger.py --classify-with-ai all --dry-run
```

Последняя команда **не создаёт выходные PDF**, но всё равно может выполнить AI-запросы и сохранить кэш — это не офлайн-проверка. Для пересборки существующего сборника после сверки плана нужен `--overwrite` или подтверждение **[1]** в меню обновления результатов.

### Настройка AI-переименования (необязательно)

1. В репозитории лежит `.env.example` — это публичный шаблон. При первом запуске `start.cmd` программа **автоматически копирует его в локальный `.env`**, даже если пользователь отменит установку Python-библиотек. Если файл `.env` уже существует, он **никогда не перезаписывается**: пользовательские ключи сохраняются при следующих запусках и обновлениях. Если запускаете Python напрямую без `start.cmd`, один раз создайте `.env` командой `Copy-Item .env.example .env`.

2. Откройте `.env` (например, командой `notepad .env`) и замените только `insert your key here` реальным API-ключом:

   ```dotenv
   PDF_MERGER_API_KEY=insert your key here
   # PDF_MERGER_AI_MODEL=gpt-4o-mini
   PDF_MERGER_AI_MODEL=gpt-6-luna
   PDF_MERGER_API_URL=https://api.openai.com/v1/chat/completions
   ```

   **По умолчанию выбран GPT-6 Luna** (точный идентификатор `gpt-6-luna`). Если нужно вернуться на GPT-4o mini, поставьте `#` перед `PDF_MERGER_AI_MODEL=gpt-6-luna` и удалите `#` перед `PDF_MERGER_AI_MODEL=gpt-4o-mini`. **Одновременно активной должна быть только одна строка модели.** Для Luna приложение отключает дополнительные рассуждения (`reasoning_effort=none`); для 4o mini используется прежний формат API-запроса.

   **Важно при обновлении существующего проекта:** `start.cmd` не перезаписывает локальный `.env` с вашим ключом. Обновление из Git заменит `.env.example`, но **не изменит выбор модели в уже существующем `.env`**. Откройте свой `.env` и вручную добавьте строки переключения, как в примере выше, оставив текущий API-ключ без изменений.

   **Пока в поле ключа стоит подсказка, AI-переименование не запускается и внешних запросов не делает.**

   Используется совместимый с OpenAI Chat Completions API; можно задать другой **HTTPS** endpoint и совместимую модель. Переменные окружения с теми же названиями имеют приоритет над `.env` (если переменная `PDF_MERGER_AI_MODEL` задана в системе, комментарии в файле не переключат модель). **Один и тот же ключ OpenAI API-проекта может вызывать разные разрешённые модели**, но это именно ключ платформы OpenAI API, а не подписка ChatGPT. Доступ к моделям и списание расходов зависят от настроек API-проекта. Для раздельного учёта и контроля расходов по приложениям желательно создавать отдельные API-проекты/ключи, а не распространять личный ключ сотрудникам.

3. Запустите `start.cmd`, подтвердите обработку и, если будут найдены нестандартные имена, выберите `[1]` для AI. Из командной строки используйте `--rename-with-ai`. Если поле ключа не заполнено, появится понятная инструкция; обработка не начнётся. Если все файлы названы правильно, ключ и сеть не нужны. Не помещайте реальные ключи в `.env.example` или Git: `.env` исключён из отслеживания.

**Что происходит:** только для PDF с неверным именем программа извлекает текст первых двух страниц (максимум 10 000 символов), отправляет этот фрагмент вместе с исходным именем файла во внешний API и получает предлагаемую дату/тип документа. Предложенное AI общее название не считается достоверным: конкретный тип берётся из локальных проверяемых признаков; иначе файл помечается как требующий проверки. Дата должна иметь подтверждение в самом фрагменте или имени файла и быть действительной. Если дата не подтверждена для одного PDF, он **остаётся без изменений**, остальные документы проверяются дальше. Только после завершения всей предварительной проверки подтверждённые файлы переименовываются в `YYYY-MM-DD-Тип.pdf`. При совпадении имени используется суффикс `-02`, `-03`; чужие файлы не перезаписываются. Если остались документы без подтверждённой даты, **создание всех итоговых PDF откладывается**, программа сообщает о неполной партии и возвращает код 1. После исправления или повторной AI-проверки этих документов объединение можно завершить, не вызывая AI заново для уже правильно названных файлов.

### Ход работы AI и диагностика

После выбора AI-режима `start.cmd` сразу показывает сообщения `[AI ...]` с номером документа, например `Документ 3/17: извлечение текста`, `запрос к AI`, `ответ AI за 2.4 с`, `дата подтверждена`. Это позволяет отличить медленное чтение PDF от ожидания сети. Запросы выполняются **последовательно**; у каждого есть сетевой тайм-аут 30 секунд (это тайм-аут отдельной операции чтения/соединения, а не строгий предел общего времени). Пока не получены ответы **по всем доступным для проверки документам**, ни один файл не переименовывается. При отклонении даты одного документа обработка не прерывается: он получает безопасный код `missing-date`, `invalid-date`, `evidence-missing` или `evidence-mismatch`, а остальные продолжают проверяться. Ошибки сети, JSON, ключа и квоты остаются блокирующими до любых переименований.

Копия прогресса сохраняется локально в `logs/ai-progress.log` (папка `logs/` исключена из Git). Этот журнал содержит только время, номер документа, этап, модель, количество извлечённых символов, задержки и безопасные коды ошибок. **Название проблемного PDF и человекочитаемая причина будут видны в локальной консоли**, но не в файле журнала. В частности, по одному журналу можно определить документ №16/17, но не восстановить его имя или точный ответ AI. **API-ключи, имена PDF и извлечённый медицинский текст в журнал не записываются.** Если запись журнала недоступна, обработка продолжается с выводом в консоль.

При ошибке HTTP 401 проверьте ключ API; 403/404 — доступность выбранной модели; 429 — квоту, лимиты и биллинг; 400 — параметры запроса и совместимость модели. Ошибка и номер документа выводятся до перехода к объединению. `Ctrl+C` прерывает процесс; если предварительная проверка ещё не завершилась, исходные имена останутся прежними. Если появилась строка `НЕПОЛНАЯ AI-ПРОВЕРКА`, проверьте показанный в консоли файл. Успешно подтверждённые исходники уже получили новые имена, но итоговые PDF **не созданы и не перезаписаны**. Следующий запуск с AI отправит только оставшиеся PDF без подтверждённой даты; затем все будут обработаны локально. При новом разборе после ранее неудачного запуска без этого исправления первый повтор может потребовать новых API-запросов, потому что старые ответы не были сохранены.

Для первого теста рекомендуется использовать один **синтетический, не медицинский** PDF. При сбоях в отчёте техподдержке можно показать `logs/ai-progress.log`, но дополнительно проверьте журнал перед отправкой.

**Проверка новой модели:** в автоматических тестах проверяются переключение модели и формат запросов без реального API-ключа. Работа Luna на конкретном API-проекте и корректность распознавания дат требуют отдельного теста на синтетическом PDF: возможны ограничения доступа к модели и расходы за токены.

**Ограничения:** для PDF-сканов без текстового слоя OCR пока нет. Если дату невозможно подтвердить или API недоступен, переименование и объединение прерываются с ошибкой; исходные имена остаются без изменений, если сбой случился до стадии переименования. При системной ошибке файловой операции ранее переименованные файлы могут остаться под новыми именами, но их содержимое не удаляется. В `--dry-run --rename-with-ai` файлы не изменяются, **однако запросы в API всё равно отправляются** и могут тарифицироваться.

### Конфиденциальность и ограничения

Обычный режим работает локально — без API, OCR и телеметрии. В **AI-режиме** извлечённый текст и имя файла передаются поставщику внешнего API, поэтому могут содержать персональные и медицинские сведения; используйте AI только при наличии правового основания, разрешения на такую передачу и подходящих условий обработки данных у провайдера. **Полные PDF-файлы не отправляются.** Репозиторий публичный — никогда не добавляйте медицинские PDF или `.env` в Git. `.gitignore` исключает `input/`, `output/`, все PDF и файлы `.env`.

Подписи в объединённом PDF становятся недействительными; интерактивные формы и вложения могут сохраниться не полностью. Для юридически значимых подписанных документов используйте оригиналы.
