# Windows UI acceptance checklist

Запускать в отдельном чистом клоне без медицинских данных. Все действия — двойным щелчком по `start.cmd`.

1. **Без папок**. В чистой копии репозитория убедиться, что `input/`, `output/` и `.venv` отсутствуют. Запустить. Обе папки созданы, выводится сообщение о необходимости установить дополнительные библиотеки. Ввести `0`: установка отменена и `.venv` отсутствует; окно держится до нажатия клавиши. Запустить снова, нажать Enter в реальной консоли (или `1` для автоматизированного теста): создаётся `.venv`, устанавливаются библиотеки, программа завершает запуск без обработки PDF.
2. **Пустая папка**. Запустить повторно. Сообщение «PDF-файлы не обнаружены»; окно держится; `.venv` уже создана, повторного предложения установки нет.
3. **Подтверждение**. Положить два искусственных PDF с одной датой. Запустить. Появляется счётчик `2`, пункты `[1] Да, запустить проверку` и `[0] Нет, выйти`.
4. **Отмена**. Ввести `0`. Результат не создан, окно ждёт клавишу; зависимости, установленные ранее, сохраняются.
5. **Запуск**. Для двух искусственных пустых PDF без доказанного типа и с правильными датами ввести `1`: оба файла должны оказаться **отдельно** в `output/На_проверку/` (пустые PDF не считаются лабораторными). Для подтверждённых лабораторных документов одного дня ожидается один сборник в `output/Анализы/`. Окно держится.
6. **Повтор**. Запустить снова с `1`. Существующий итог не перезаписан.
7. **Ошибка/отсутствие Python**. В чистой среде без установленного Python запустить с файлами, нажать `1`. Отображается понятная ошибка и окно держится до клавиши.
8. **Старый ярлык**. `merge_windows.bat` открывает то же меню и тоже не закрывается до клавиши.
9. **Проверка кириллицы**. Убедиться, что кириллические названия папок и PDF корректно отображаются на Windows PowerShell 5.1.

В Git/CI не используются реальные медицинские PDF.

10. **Неправильное имя, AI отменён**. Добавить `scan.pdf`. Запустить, нажать `1`. Проверить предупреждение о передаче текста, выбрать `0`: ни переименования, ни объединения нет.
11. **Только локально**. Для `scan.pdf` выбрать `1` → `2`: файл останется в `input`, объединения для него нет, в сеть ничего не отправляется.
12. **AI без ключа**. Выбрать `1` → `1` без `.env`: должно появиться сообщение с `PDF_MERGER_API_KEY`, входной PDF не меняется.
13. **AI с ключом (только тестовая документация)**. Создать `.env` с тестовым ключом провайдера и синтетический PDF с датой, подтвердить передачу; проверить переименование и итоговый файл в одной из структурированных подпапок `output/`. Если тип не доказан, файл находится в `На_проверку/`. *Не использовать реальные медицинские данные*.
14. **Корректные имена**. Для `YYYY-MM-DD-Название.pdf` дополнительное AI-меню не выводится, ключ и сеть не нужны.

15. **Изменение требований**. При наличии `.venv` временно изменить `requirements.txt` на заведомо неудовлетворённое требование (только на тестовом клоне). На следующем запуске программа предлагает установку. Ввести `0`, убедиться, что объединение не началось. Вернуть `requirements.txt` и проверить отсутствие повторной установки.
16. **Сбой pip**. В тестовой копии имитировать недоступный пакет/интернет. Установка завершается с понятной ошибкой; PDF не изменяются и окно остаётся открытым.

17. **Подтверждение Enter**. В настоящем окне Windows PowerShell 5.1 (без перенаправленного stdin) нажать пустой Enter на запросе установки: должно начаться создание `.venv`. При автоматическом тестировании допустимо вводить `1`, поскольку пустой stdin и Enter могут быть неразличимы при перенаправлении.

18. **Автосоздание шаблона .env**. В чистом клоне убедиться, что `.env` отсутствует, а `.env.example` есть. Запустить `start.cmd`: `.env` создаётся до установочного запроса, содержит `PDF_MERGER_API_KEY=insert your key here`, но никаких реальных ключей. Даже при отмене установки файл остаётся.
19. **Сохранение ключа**. Записать тестовое значение в `.env` (не реальный ключ), запустить `start.cmd` повторно. Убедиться, что `.env` не перезаписан; новая версия `.env.example` также не должна менять `.env`.
20. **Плейсхолдер не считается ключом**. Для синтетического PDF с неправильным именем выбрать AI без замены текста `insert your key here`: должно появиться сообщение о необходимости заполнить ключ; сетевого запроса быть не должно.

21. **Переключение моделей в .env**. В тестовом `.env` оставить `# PDF_MERGER_AI_MODEL=gpt-4o-mini` и `PDF_MERGER_AI_MODEL=gpt-6-luna`: приложение выбирает Luna. Поменять комментарии местами: выбирается 4o mini. API-ключ не меняется, повторной установки библиотек нет.
22. **Неоднозначная конфигурация**. Оставить обе строки `PDF_MERGER_AI_MODEL` без `#`. AI-режим должен завершиться понятной ошибкой до отправки запроса; офлайн-слияние по-прежнему доступно.
23. **Обновление существующей установки**. После `git pull` убедиться, что заполненный локальный `.env` остался прежним (в том числе выбранная там модель). Для переключения открыть и вручную изменить `.env` — содержимое обновлённого `.env.example` не копируется поверх существующего файла.

24. **Прогресс AI на консоли**. На синтетическом файле с неправильным именем выбрать `1` → `1`. Сразу должны появиться строка о старте и этапы `Документ 1/1`: чтение PDF, запрос к API, ответ AI/ошибка, проверка даты. Дождаться вывода или `Ctrl+C`, ничего не блокируется без объяснения.
25. **Локальный журнал**. Убедиться, что `logs/ai-progress.log` содержит только номер документа, время, этап и безопасные коды ошибок, **без API-ключа, ФИО, имён PDF и текста**. Журнал не должен попасть в `git status`.
26. **Отказ API**. На тестовом ключе/модели проверить понятный HTTP-код и подсказку (401/403/404/429), отсутствие переименований до успешной проверки всех дат и возможность повторной попытки.

27. **Анализы и обследования одной даты**. На синтетических PDF с явно прописанными признаками ОАК, биохимии крови и рентгенографии убедиться: один `output/Анализы/YYYY-MM-DD-Анализы.pdf` содержит только лабораторные результаты; `output/Обследования/YYYY-MM-DD-Рентгенография ...pdf` содержит только рентгенографию.
28. **Два обследования за день**. Два отчёта об одном типе исследования не должны объединяться и получают имена с суффиксами `-02` и т. д.
29. **Старые смешанные результаты сохранены**. Поместить прежний `output/YYYY-MM-DD.pdf`. Запустить новую обработку: старая копия должна остаться неизменной, новые результаты — в подпапках; не удалять старые файлы автоматически.
30. **Ранее ошибочно названное исследование**. `YYYY-MM-DD-Тесты.pdf` с текстом «Рентгенография ...» должно попасть в `Обследования`, без API-запроса; только наличие даты в имени не означает лабораторный анализ.
31. **Отсутствует текстовый слой**. Скан/пустой PDF без достоверного типа должен попасть отдельным файлом в `На_проверку` и не объединяться с анализами, даже если имя содержит «Анализы» или «Биохимия».

32. **Неподтверждённая дата у 16-го из 17**. На отдельном тестовом наборе синтетических PDF с неправильными именами имитировать 15 достоверных ответов, один ответ с неподтверждённой датой и следующий достоверный ответ. Проверить: программа не зависает и идёт до конца, отмечает конкретный документ в консоли, в локальном логе — только индекс и безопасный код, без имён/текста; подтверждённые файлы получают правильные имена, сбойный остаётся без изменений; папка output **не изменяется**, код возврата 1.
33. **Повторная обработка**. После частичного результата повторить AI: запросить только оставшиеся PDF без даты. После успешного завершения сформировать сортировку «Анализы/Обследования/На_проверку», не потеряв ни одного документа и не перезаписав старые результаты без разрешения.
34. **Ошибка сети или биллинга**. Имитировать HTTP 429 после одного успешного AI-предложения. Весь preflight должен завершиться ошибкой **до любого переименования**; прежние файлы и output не меняются.

35. **Системная шапка лабораторного исследования в рентгенографии или ЭКГ**. Синтетический PDF содержит «Дата назначения лабораторного исследования», затем код `7002892` с рентгенографией или `7014145` с электрокардиографией. Проверить, что результат определяется по **реальной выполненной процедуре**, в `output/Обследования` появляется конкретное имя, и ложной папки `На_проверку` не возникает.
36. **УЗИ только в рекомендации**. В описании рентгенографии есть «Рекомендовано УЗИ»; убедиться, что программа классифицирует единственную выполненную рентгенографию и не принимает рекомендованную процедуру за выполненную.
37. **Повтор после PR #8/#9**. Для файлов `input/YYYY-MM-DD-Требует-проверки*.pdf` запустить `--dry-run` без `--rename-with-ai`. Убедиться в переименованных результатах `output/Обследования`, неизменности исходников и старых результатов. В старые `output/На_проверку` программа не вмешивается. Даты выполнения, расходящиеся с префиксом, требуют отдельной проверки.

38. **Одна кнопка «обновить и запустить»**. В чистом тестовом Git-клоне с локальным `.env`, `input/`, `output/`, `logs/` открыть `update-and-start.cmd` из проводника/через ярлык (в том числе когда PowerShell открыт в `logs`). Должно выполниться `git pull --ff-only origin main`, после чего появится привычное меню `start.cmd`.
39. **Локальные изменения**. Изменить отслеживаемый файл в тестовом клоне и запустить `update-and-start.cmd`. Он должен сообщить о незакоммиченных изменениях, **не обновить/не запустить приложение** и не тронуть `.env`/PDF.
40. **Ошибка обновления**. В тестовом клоне сделать расходящиеся коммиты локально и в `origin/main`. `git pull --ff-only` должен завершиться ошибкой; обработка PDF не начинается, без `reset --hard`/force. При отсутствии Git должен быть явный отказ, а `start.cmd` отдельно всё ещё работает офлайн.

41. **Ложные лабораторные процедуры из диапазонов**. В синтетических CBC, биохимии и КЩС добавить референсы `110.0 - 160.0`, `320.0 - 360.0`, `135.0 - 145.0`. Все должны попадать в `Анализы`, не в `На_проверку`. При этом цифровой код реально выполненной рентгенографии из семи цифр продолжает маршрутизироваться в `Обследования`.
42. **Пересборка старых неполных результатов**. Создать дневной сборник с одним лабораторным исходником, затем добавить второй исходник того же дня. При повторном `start.cmd` выбрать `[2]` — старый PDF сохраняется, CSV ставит `НЕ ПОДТВЕРЖДЕНО`. Затем выбрать `[1]` — дневной сборник содержит оба исходных PDF, CSV отмечает `СОЗДАНО / ДА`; старый `На_проверку` без удаления сохраняется с предупреждением.
43. **Отчёт о включении**. Проверить `output/Состав_результатов.csv` в Excel: кириллица читается, разделитель `;`, для пропущенных файлов нет ложного подтверждения, `--dry-run` не пишет отчёт, ошибка записи необязательного CSV не отменяет успешно созданные PDFs.
